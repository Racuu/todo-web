# 维护与交接

## 按改动验证

- 菜单或详情改动用虚构任务检查桌面右键、手机更多操作、窄屏菜单边界、返回和关闭。两个入口操作同一数据时，核对结果一致。
- 日期或排序改动检查今天、明天、日期区间两端和跨月示例。切换清单再返回，检查各自的排序以及已完成任务的展示。
- 涉及数据结构、移动或删除时，用测试数据走一次备份、恢复和筛选。覆盖空组、空清单、已完成任务、旧版备份和同 ID 差异。同步改动另用两个测试会话修改同一记录，确认冲突不会覆盖已提交的数据。
- 纯文档变更检查索引跳转、原文小节和代码定位名称。最终告诉用户实际验证了什么，以及是否仍有影响使用的未验证项。

已出现的问题保留可复现案例和验证环境。iPhone 步骤长按误选的案例为：长按第二个步骤拖到首位，确认顺序、系统选区和松手后的编辑状态，再轻点文字编辑。393 像素宽 Chromium 模拟已验证；iPhone 真机待验证。修改触摸手势时分别记录模拟与真机结果。

## 发布与回退

GitHub Actions 在发布前运行 `verify-index.py` 和 `verify-my-day.cjs`。前者核对索引中的文件、小节及代码定义；后者在隔离的 Chrome 中用虚构任务操作详情和右键菜单，并核对改期移出、任务拖动后的顺序持久化与窄栏标题宽度。部署作业依赖检查通过。每次维护另按受影响行为做语义核对；涉及数据的约定优先保留为回归测试。

网页入口是 main 分支的 index.html。发布前检查差异范围。网页有改动时核对 GitHub Pages 对应提交的部署状态，再从已发布网址复查本次改动。缓存可能影响观察，可用本次提交号作临时查询参数。

网页需回退时，通过新提交撤销相应前端改动。数据恢复是独立操作，先核对目标私有库、备份和同 ID 差异的处理方式。

## 跨会话交接

一项行为只在对应主题维护一份说明。修改行为、字段或发布方式时，在同一次变更中更新对应小节。文件或函数改名时同步修正根索引。纯样式微调无需追加开发日志。

任务中断且确有后续工作时，才在根目录写 HANDOFF.md，简记目标、已完成与验证、剩余问题、下一步。接手者核对当前代码后继续，完成后移除交接文件。公开文档中的示例用虚构记录，私有任务内容和令牌均不写入。
