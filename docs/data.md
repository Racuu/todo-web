# 数据、同步与恢复

## 关系与排序

| 私有库路径 | 关联和含义 |
| --- | --- |
| `groups/{id}.json` | `id` 是组的 UUID，`name` 是显示名。保留空组。 |
| `lists/{id}.json` | `group` 引用组 ID，空值或缺失表示未分组。`position` 为可选的组内位置，`sort` 为本清单中任务的排序方式。两个字段均随清单同步。保留空清单。 |
| `tasks/{首位}/{id}.json` | `list` 引用清单 ID。兼容旧版空清单引用。标题、步骤、备注、完成与重要状态均保留。 |

重命名或移动时保留 ID。同名组或清单用 ID 区分。取消分组会清空清单的组引用；删除清单会将清单和其中未删除的任务一起标为 `deleted: true`。保留标记可供备份和恢复检查。

每个组分别排列清单，未分组清单也自成一列。有 `position` 的清单按非负整数升序排在前面。相同位置或缺少位置时按中文名称自然排序，再按 ID 排序。旧备份可以省略该字段。手动调整一次提交所需的清单记录。跨组、取消分组或复制清单时清除原位置，新建清单也从默认名称顺序开始。完整 JSON 保留这个字段。

清单中任务的排序值为 `star`（重要性）、`due`（到期日期）、`day`（我的一天）、`name`（字母顺序）、`created`（创建日期）、`manual`（手动，缺省值）。`day` 和 `due` 是本地 YYYY-MM-DD 日期或空串。`created` 使用 Unix 毫秒。重复任务还可含 `repeat` 和基准日期 `repeatAnchor`。

手动拖动只更新被移动任务在该视图的位置字段（`listRank`、`dayRank`、`starRank`、`planRank`、`legacyRank` 或 `searchRank`）。按十六进制位置前缀、去掉连字符的任务 ID 和末尾 8 拼成的字符串升序排列。缺省前缀为最大安全整数减创建时间的 14 位十六进制值，计划内再前置 YYYYMMDD。JSON 保留位置字段。

“我的一天”按设备本地日期筛选。包含 `day` 等于当天的任务，也包含未完成且 `due` 等于当天的任务，后一类排除 `dayDismissed` 等于当天的记录。两类均过滤已删除的任务和清单。`dayDismissed` 是可选日期，旧数据缺少时按空值处理。选择今天到期时，截止日期和加入日期随同一条任务保存；提前排期的任务在到期当天由本机直接显示。JSON 保留原始字段，CSV 的“我的一天”包含导出当天自动加入的任务，并另列手动移出的日期。

## 同步与令牌

设备按仓库和分支用 IndexedDB 保存已确认的文件和待上传的任务修改。首次连接验证仓库为私有并读取全量。已有缓存时先开放本机操作，后台对比分支提交，仅在版本变化时检查文件 SHA 并下载有变化的记录。升级分目录版本时，先原子检查旧版待上传队列。队列为空才清空已同步缓存并首次全量载入；仍有修改时保留原库并提示。切回页面时检查更新，持续使用时每分钟检查一次。

新建任务以及普通任务的标题、完成状态、重要性、日期、步骤和备注先写入本机。连续修改约一秒后合并上传。页面显示“已存本机”后关页，重新连接同一仓库可继续发送。GitHub 限流时按返回的时间退避。不同字段自动合并，同字段冲突在右上角选择本机或云端版本。步骤按整组比较。删除和编辑冲突保留两种版本供选择。

清单结构调整、任务跨清单移动、完成重复任务及恢复备份时，先处理待上传任务，再校验关联记录版本。多记录修改通过一次快进提交完成。备份导出包含本机待同步任务的当前版本，冲突的另一版本仍在同步冲突界面。

细粒度令牌限定一个私有数据仓库。各设备可使用同一枚令牌。勾选记住令牌时跨次打开可直接登录，取消勾选时令牌只保存在当前标签页会话。任务缓存和未上传修改独立于令牌。主动断开会清除凭据，没有待上传内容时也清空此仓库分支的本机缓存。

## 备份与恢复

将每条记录写为 UTF-8 JSON。组写入 groups/{id}.json，清单写入 lists/{id}.json，任务写入 tasks/{首位}/{id}.json。首位取任务 UUID 的第一个字符并转为小写（0–9 或 a–f），文件名保留原 ID。保留全部字段、空组、空清单和删除标记。用清单的 group 关联组 ID，用任务的 list 关联清单 ID，按原字段恢复步骤和排序。

完整文件是 UTF-8 JSON，`format` 为 `to-doo-backup`，目前导出 `version: 3`，含 `groups`、`lists`、`tasks` 数组，保留空容器、原 ID、归属、步骤、排序及删除标记。也可导入第 1、2 版。第 3 版的 fields.restore 内含以下恢复说明，fields.guide 指向本节。CSV 按任务逐行导出，带组和清单的编号与名称，适合表格筛选。恢复层级使用完整 JSON。

1. 在备份页面选中 JSON 可先本地预览。校验格式、版本、重复 ID 和父子引用，再核对组、清单及任务。
2. 在 To Doo 中选好目标私有库后恢复。默认只补缺失项，同 ID 有差异时保留云端版本。用户明确选择替换差异后才覆盖。只存在于目标库的记录保留。
3. 使用其他工具时，可在空的、已初始化分支的私有仓库中，将三个数组内每条记录按上表路径写为 UTF-8 JSON。保留原 ID、全部字段及引用。其他程序可直接按组 ID 关联清单，再按清单 ID 关联任务，无需原聊天或 AI 服务。
4. 恢复后核对组、清单、任务数量（区分已删除项），再抽查同名清单、空清单、步骤和完成状态，按组、清单和状态筛选一次。
