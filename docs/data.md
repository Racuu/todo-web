# 数据、同步与恢复

## 关系与排序

| 私有库路径 | 关联和含义 |
| --- | --- |
| `groups/{id}.json` | `id` 是组的 UUID，`name` 是显示名。保留空组。 |
| `lists/{id}.json` | `group` 引用组 ID，空值或缺失表示未分组。`sort` 属于该清单，因此在设备间同步。保留空清单。 |
| `tasks/{id}.json` | `list` 引用清单 ID。兼容旧版空清单引用。标题、步骤、备注、完成与重要状态均保留。 |

重命名或移动时保留 ID。同名组或清单用 ID 区分。取消分组会清空清单的组引用；删除清单会将清单和其中未删除的任务一起标为 `deleted: true`。保留标记可供备份和恢复检查。

排序值为 `star`（重要性）、`due`（到期日期）、`day`（我的一天）、`name`（字母顺序）、`created`（创建日期，缺省值）。`day` 和 `due` 是本地 YYYY-MM-DD 日期或空串。`created` 使用 Unix 毫秒。重复任务还可含 `repeat` 和基准日期 `repeatAnchor`。

## 同步与令牌

浏览器直接访问 GitHub，通过 `verifyPrivate` 确认数据仓库为私有。已选配置是一枚细粒度令牌、无到期日、只授权单个数据仓库，各设备分别输入同一枚。勾选“在此设备保存”使用该浏览器的 localStorage；不勾选使用 sessionStorage，当前标签页刷新后仍可用，标签页会话结束后需重新输入。

读取从当前分支获得记录。普通更新用文件 SHA 检查版本。取消分组、复制或删除清单等多记录更新由 `commitChanges` 核对相关版本，再一次提交，更新分支时使用 `force: false`。处理冲突应重新读取云端，保护另一台设备已提交的更新。

## 备份与恢复

完整文件是 UTF-8 JSON，`format` 为 `to-doo-backup`，目前导出 `version: 2`，含 `groups`、`lists`、`tasks` 数组，保留空容器、原 ID、归属、步骤、排序及删除标记。读取兼容缺少组的第 1 版。CSV 按任务逐行导出，带组和清单的编号与名称，适合表格筛选。恢复层级使用完整 JSON。

1. 在备份页面选中 JSON 可先本地预览。校验格式、版本、重复 ID 和父子引用，再核对组、清单及任务。
2. 在 To Doo 中选好目标私有库后恢复。默认只补缺失项，同 ID 有差异时保留云端版本。用户明确选择替换差异后才覆盖。只存在于目标库的记录保留。
3. 使用其他工具时，可在空的、已初始化分支的私有仓库中，将三个数组内每条记录按上表路径写为 UTF-8 JSON。保留原 ID、全部字段及引用。其他程序可直接按组 ID 关联清单，再按清单 ID 关联任务，无需原聊天或 AI 服务。
4. 恢复后核对组、清单、任务数量（区分已删除项），再抽查同名清单、空清单、步骤和完成状态，按组、清单和状态筛选一次。
